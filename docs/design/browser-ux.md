# Shared Browser 交互规格

设计提案。以[主规格](browser.md)和[协议](../api/browser.md)为约束，不要求替换现有设计系统。界面使用现有 Button、反馈、Composer、ApprovalRequest、任务资源与差异查看入口。

## 1. 信息结构

浏览器位于现有右侧工作区，可切换分栏/扩展视图，保留聊天输入与当前 Thread 身份。固定顶栏包含返回、前进、刷新/停止、地址、Page tabs、视口和“由谁控制”。控制入口始终可见且不被网页覆盖。后台 Thread 的 Browser 活动不得抢焦点、展开用户正在阅读的另一面板或切换当前聊天。

浏览器与聊天之间显示简洁的活动条：操作中的目标描述、进度和“接管”。长流程展示最近一次动作而非每条 CDP 消息。完成时展示验证结果卡，可展开截图、检查与代码变更；历史卡不是可交互直播。

## 2. 控制模式

| 状态 | 用户看到 | 可用操作 | 退出条件 |
|---|---|---|---|
| human | “你在控制；Agent 观察已暂停” | 正常页面交互、批注、交还 | 用户明确交还 |
| agent | “Agent 在控制”与动作标签 | 接管、只读跟随；页面直接输入被可信遮罩阻止 | 接管/撤销/操作完成保留策略 |
| transferring | “正在交接”，同时说明在途结果可能未知 | 本机接管始终可用；不允许新 Agent 输入 | 栅栏已更新并结算可知部分 |
| waiting approval | 聊天中的现有审批卡，实际站点/动作摘要 | 允许/拒绝、接管 | Core 决定到达，不能凭按钮点击本地放行 |
| unavailable | 页面/宿主失效原因与恢复影响 | 恢复、核对历史；不显示伪直播 | 明确恢复并重新授权 |
| unknown | “操作结果未确认，不会自动重试” | 打开页面核对、查看回执、检查确认 | 用户核对并另发后续请求；旧记录不改 |

接管按钮首先立即建立本机栅栏；真实输入开放要等本机合成输入收敛。无法收敛时保留“正在交接”，提供停止/关闭页面，不能让人和在途输入争写。这个过程不等待Core批准。

“停止页面加载”“接管浏览器”“停止当前 Turn”“停止后台服务”是四种不同操作，标签和快捷键不可混同。浏览器接管不强制中止正在运行的无关开发服务器。

## 3. 核心场景

### A. 同页让 Agent 检查

用户已有输入未提交的页面 → 点击“让 Agent 检查当前页” → 显示当前 Thread 和URL、授权范围 → Core/Host 绑定相同 Page → 语义观察/按需截图 → 回复附证据。必须验证原生 WebContents 身份和隐藏 sentinel，不能仅比较URL。模型想新开同URL时优先告知已有可认领Page，而非静默重复。

### B. 人工登录后交还

Agent 遇到登录/权限/高影响提交 → 页面保持打开 → 用户接管 → Agent 的自动读与诊断暂停 → 用户手工操作 → “交还并继续” → 新观察 → 根据实际结果继续。没有跨重启登录承诺。窗口遮挡/切换本身不是交还授权。

### C. 区域批注

用户进入批注 → 暂停 Agent 并取得 human 控制 → 生成带Page/视口来源的捕获 → 暂藏native页面，显示捕获（标“截图反馈，页面可能继续变化”） → 拖选区域/输入评论 → 草稿卡附缩略图、URL、时间 → 用户明确发送到原Thread。取消恢复native页面，不改变导航。原Thread切换后草稿不漂移，发送前提示目标。

冻结截图是首期可靠基础路径，不把它宣传成 live DOM overlay。既有原生叠层能力通过真实测试后，可增加实时选择；两条路径产生相同批注数据。

### D. 元素批注

在human控制的页面中选择元素 → Controller提供当前Ref/role/name/bounds与裁剪证据 → 用户补充描述 → 送入Composer。选择器只返回页面事实，不能暴露产品IPC。DOM在选择和发送间变化时保留原证据并标stale；Agent先重看，不能执行旧Ref。无语义或跨源不可达时退回区域批注，而非生成猜测selector。

### E. 改代码并验证

Runtime启动或复用当前项目的服务 → 把真实已知端口交给Browser → 查看现状 → 用户批注 → Agent读代码并修改 → 等待已观察的热更新/页面条件 → 新观察/截图 → 检查表单行为及目标视觉 → 结果卡关联工具call、变更和证据。行为成功、视觉判断、人工认可分别显示；不能用“编译通过”替代视觉验收。

### F. 临时样式试改

仅human模式，支持有限属性（文本、颜色、字体、间距、尺寸）及撤销/重做；始终显示“页面试改，未写入代码”。记录原值和文档身份，只恢复由本次试改创建的覆盖；导航/HMR替换元素后停止回放并提示失效，不覆盖应用的新状态。用户可发送意图与前后证据，Agent再修改源码。刷新会清除临时覆盖；最终验证需在覆盖清除后进行，防止试改掩盖未改源码。

## 4. Native View 特有约束

React z-index不能被当作盖住WebContentsView的方案。可信原生overlay或独立本地视图需要处理resize/focus/IME、窗口遮挡和屏幕DPR；网页不能包含相同权限的preload。Agent控制时遮罩阻止用户输入但保留接管；human控制时撤销Agent准入。截图采集针对网页内容，默认不包含Agent光标、操作标签或工具栏。

在渲染窗口隐藏/最小化、页面后台和视口为0的情况下，不伪造截图或用旧图作为新证据；能力不足时提示需要可见页面。首期无需为此建设远程视频编码器。

DevTools由用户显式打开。打开前暂停Browser自动化，detach事件置不可用；关闭后重新attach、提升相应代次并重新观察，旧 preparedAction 无效。若某版本允许多调试会话也不能依赖这种行为绕过所有权。

## 5. 响应式、坐标与输入

控制页面的CSS视口与GUI显示缩放分开保存。固定视口初值可采用1280×720；调节范围320–3840×320–2160是可配置的初始策略，不是依赖浏览器默认。截图同时记录bitmap和CSS尺寸。缩放后必须测试中心、边缘、滚动后位置、iframe与Canvas输入；1×、2×屏幕和不同页面zoom覆盖。

只有处于human模式的真实键盘输入直接进网页。中文输入法确认Enter不发送评论/聊天；接管时清理合成按键但不干扰用户正在合成的文本。Tab键导航可到达接管、授权、URL、tabs、批注发送/取消；焦点恢复到发起入口。控件带文本标签，控制状态改变用可访问通知，不依赖颜色。

## 6. 文件和权限

弹窗先归因opener、Thread和临时上下文，再决定显示/阻止；不创建未归属窗口。跨站登录跳转要重新检查访问范围。原生相机/麦克风/定位等首期默认拒绝并交给用户，不自动接受浏览器权限提示。

下载展示来源、名称、大小（未知时标未知）和状态；用户确认目标后保存，不执行文件。上传先交给用户的可信选择器，取消是正常可恢复结果；首期不让Agent指定任意文件路径。文件选择完成后，接管期间内容不自动被Agent读取。

## 7. 验收材料

每个发布候选应有同页交互、接管/交还、区域与元素批注、临时样式清除后的验证、错误与不可用状态的真实截图或短录屏。验证状态显示“未验证/通过/失败/结果未知”，不使用单一success绿标掩盖不同含义。详见[测试矩阵](../development/browser-testing.md)。
