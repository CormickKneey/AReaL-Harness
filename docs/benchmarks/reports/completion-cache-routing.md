# 收尾、读取补位与 Responses 路由对照

冻结候选 `1ee7d4ab` 的固定100次开发集对照没有通过组合性能晋级门槛。双方各49/50正常结束且通过冻结行为验收，产物各50/50通过；48个正常正确配对覆盖十题，任务等权墙钟比为 **1.3058**，AReaL仍慢约30.6%。缓存输入占比已接近，但不能据此声称整体效率追平。完整可移植数据见[汇总](completion-cache-summary.json)。

此前修复已合入 `d283badc`。本变更将读取补位、路由传递和后续契约修复整合到包含桌面任务与恢复、用量观察器改进的主分支。下列100次任务统计只对应冻结候选，后续整合版没有重新运行另一个100次；机制回归不能代替其任务级性能比较。

## 方法与尝试保留

同一 `gpt-6.1-sol`、xhigh、同一上游订阅链路；十题每方独立五次，三根槽/方滚动补位。共同根墙钟1200秒、实际HTTP请求160次；已观测输入/输出阈值为500万/16万token，缺失消费不补零，阈值不保证未知消费也受完整计量。保留各产品原生工具协议、工具组合及内部恢复行为；Codex的code-mode调用数不能与AReaL平铺工具数直接比较。

本组不传 `maxModelRounds`；读取宽度4、`completionFocus=true`及bounded网络恢复仍是显式实验配置，不能称为默认GUI。此前冗余的1024轮参数会每轮追加用户角色提示，其29个已准入根（AReaL10/12、Codex17/17正常正确）及71个未准入完整保留；另有4个试运行根和84次短机制请求，不混入正式100次。所有失败均未用成功重跑替换。

十题均为已见开发任务，覆盖Web聊天室、可恢复DAG、存量API、发布流水线、经营对账、事故取证、发布交接、知识门户、内容寻址备份与离线文档构建。八题显式需要或允许并行，两题由Agent判断；不代表长期四领域各25%的整体分布，也不是来源隔离确认。

## 通用机制与范围

| 问题类别 | 修复与回归 | 保守边界 |
|---|---|---|
| 连续可信读取等待慢调用整批收齐 | 可信能力声明的连续读取在屏障之间按空闲槽滚动补位；不匹配读取的全局hook不再造成无关串行 | 默认宽度1；Shell、外部工具、匹配hook、有限输出和重复失败门禁保留屏障，不按命令外观猜安全 |
| 会话路由丢失 | 内置订阅适配器传递稳定会话身份与首次Turn状态；通用Core Responses HTTP也覆盖自定义端点，隔离模型构建、Thread、Turn与用途 | 工厂池128项、空闲30分钟、单值8KiB；账号变化、回收和迟到响应不污染新槽；无所有者不共享，正文和重试策略不变 |
| App数据改变系统前缀 | 将App引用从每Turn系统快照移为变化时追加的areal_context数据；保留A→B→A、清空和原历史 | 真实Core/MCP更新回归保持完整旧请求前缀；恢复旧插入路径的源码变异会失败。该跨Turn路径未包含在单Turn十题内 |
| 大批交接变成头尾字符串 | 完整原文可回取时，优先保留结构化生命周期、来源、交付和游标，正文为UTF-8预览且nextOffset按实际字节更新 | 不把预览当完整正文或验收；元数据仍超限时使用既有有界原文回取，不吞掉未知结果 |
| 新权限审核用途占住模型名额 | permissionReview接入求解/摘要同一实际请求容量，退避释放、重试重新准入记账 | 真实Core/Runtime容量1、503退避、活动流占位及取消不执行回归通过；仍保留20秒、512token和无工具限制 |
| 子任务当前环境能力不清 | sourceView区分快照与当前共享环境；networkPolicy和基础scope创建共用策略，deny涵盖本地监听 | 事实说明不授予网络；隔离或旧执行器无法确认时返回unknown |
| 后期验收与收尾规划 | 显式实验指引提前安排有限验收、文档及当前源集成检查 | 组合没有通过耗时门槛，保持默认关闭，不强制成功、跳过验证或截断最终答复 |

旧环境反馈修复 `0b3130e3` 未回退。本组AReaL3200、Codex3846次相邻请求中，已捕获旧input均保持严格前缀，顶层instructions/tools变更均为0；Native Lite工具也可能编码在input中。此前大缓存差距发现的路由缺失经短探针和本组支持，但不预设所有端点的服务端路由相同。

此前工具链继承、隔离完整报告、取消终态消费、能力/写集合说明、安全共享租约、求解/摘要容量、Git感知快照与制品就绪修复继续保留，见[上一轮](complex-work10-completion-runtime.md)。共享资源未结算、UNKNOWN或一致性无法确认时仍不能随意释放写租约；快照仍有大小、符号链接和依赖环境边界；默认持续网络恢复仍兼容，本机使用显式bounded。

## 验证与推广决定

各Rust目标分段补齐后共1197项通过、14项忽略；GUI173通过、3跳过，另57项provider契约/恢复通过，类型、构建和真实Core/Runtime协作冒烟通过。第一次整套流程在链接时耗尽磁盘，第二次四个目标无法运行损坏产物；隔离这些产物并重建后只补跑失败目标，再完成launcher和smoke。没有把两次整套失败改写为一次绿色make verify，也没有重复已通过的长测试。

保留权限探针初版工作区错误、机制RED、App源码变异RED、下载和原始Electron资源签名预检失败。Electron归档按锁定npm校验和验证；最终本地包另行签名和严格深度验证，不能声称上游归档已有完整资源签名。

HTTP身份/状态传递、追加式上下文、容量生命周期和结构化回执按传输/正确性不变量验证；整合版本没有继承冻结候选的整体提速结论。性能策略不扩大为全局默认，来源隔离确认仍缺失。本机关闭新收尾指引，既有显式读取宽度4保留为实验设置；全局默认仍为1/false。完整主工作区备份、实际安装版本/哈希、配置与40会话迁移核验保存在私有交付资产，安装身份以运行包manifest为准。自定义GUI端点的实际缓存比例尚未直接测量，不能把固定订阅链路的92.82%转为任意provider保证。
