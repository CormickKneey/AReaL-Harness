## 通用机制与保守边界

| 问题类别 | 修复 | 范围、反例与兼容性 |
|---|---|---|
| 同一响应所有工具串行 | 连续可信内置只读批次有界并发；先按调用顺序持久化意图 | 仅明确的 Builtin 文件读取、列举、状态和搜索；写入、游标、进程输入和未知后端形成顺序屏障。hooks、有限输出等情形仍串行；取消收齐在途，UNKNOWN 不跨越写屏障。全局默认宽度仍为 1，本机显式为 4 |
| 共享作者等待模型仍持有整轮独占租约 | 潜在副作用时取得租约；受管进程全部结算后可在等待模型边界让出；执行前复核完整共享树版本 | 工作区变化返回执行前 CONFLICT，由模型重新观察后决策，不自动重放。活跃进程、UNKNOWN、清理错误、hooks、链接、外置 Git 元数据、状态重叠和超限树保留互斥；不是逐工具无条件解锁 |
| 普通开发仓库快照失败 | Git tracked、未忽略的 untracked 和显式 writes 输入投影；无 Git 时使用描述符相对的 ignore 解析；制品收集与源码选择分开 | 单文件 16 MiB、总量 64 MiB，store 原 128 MiB 上限不变。未忽略链接、特殊文件和超限输入明确拒绝；依赖闭包与执行环境不等于源码投影。交付保留 baseline/candidate 闭包与冲突检查，不误删忽略产物 |
| 网络退避占 Engine 或共享模型池 | 在每次实际请求边界准入，HTTP 内层和 Core 外层失败先释放两层许可，再退避、重新排队并记账 | 活跃流仍占容量；摘要参与相同控制；取消、已确认工具与 Goal UNKNOWN 不自动重放；缺失消费不退款、不补零 |
| 持续恢复过久，或 bounded 完全禁用 Core 恢复 | 独立 `NetworkRetryMode`：bounded 对当前求解或摘要请求最多五次 Core 网络恢复，耗尽后不借 completion 重试绕限 | persistent 仍为全局默认；本机显式 bounded。legacy `watchdog_disable=true` 仍关闭 Core 网络恢复，HTTP 重试独立。次数上限不是整题墙钟上限；Rust `Limits` 显式构造须增加字段或使用默认展开 |
| 候选手动摘要单槽自锁 | 去掉手动入口重复取得的外层许可，统一在真实摘要请求边界准入 | 本轮候选引入，发布前发现并修复；原失败记录保留 |

## 固定对照与全部尝试

原八题保持题面，新增内容备份 CLI 和离线 Markdown 发布两题。全部是已见开发任务，不是来源隔离确认。双方模型均为 `gpt-6.1-sol / xhigh`；每根 1200 秒、根/子/辅助累计 160 请求、已观测 input 5M/output 160k。每方三个根槽滚动补位，共六根；某一方空槽不转给另一方。浏览器验收在独立影子副本执行，不占根槽。

AReaL 使用关闭调试符号的 macOS arm64 debug/dev 包，Codex 使用官方发行二进制。两者构建 profile 不同，本轮描述实际制品与模型组合，不是相同优化条件的 Runtime 排名。普通同 UID 本地对照不构成恶意探查隐藏评分的安全隔离评测。

| 阶段 | 实际根尝试 | 保留结果与限制 |
|---|---|---|
| 链路预检与功能先导 | 6 + 8 | 与正式分母分开，失败、误配环境和中间候选均保留 |
| 原十题每方五次 | 100 | 全部结算；公共转发链出现 905 次 ECONNREFUSED 和一次 ECONNRESET。58 根有直接本地 502 证据，另两根同时间段流中断。不能当作充分的五次重复能力比较 |
| 首次补充 | 6 | 单次连接重置触发过保守早停；另 14 格未准入，不补零、不算成功、不替换旧失败 |
| 最终版本单轮确认 | 20 | 全部准入并结算，完整性核验通过；结果单列，不冒充五次重复或独立来源确认 |

合计 140 次模型链路根尝试，另 14 次未准入；并不代表每次均取得真实上游响应或可知消费。原正式矩阵 AReaL 正常 15/50、正常且行为验收通过 12/50；Codex 分别为 24/50、21/50。故障端点的具体归属缺少旧日志证据，不将本地转发错误直接归给模型供应商。

编排器原来没有持续转发故障熔断，导致故障阶段仍快速补位。已补上连续三次无 HTTP 响应的连接失败或 5xx 才停止新准入，成功响应清零；原单次重置早停与三次失败探针均保留。它是评测编排修复，不计作 Agent 能力提升。

## 最终二十次结果

| 产品 | 正常结束 | 正常且行为通过 | 超时 | 验收 UNKNOWN | 已观测 input / output 下界 | 用量未知 / 全部请求 |
|---|---|---|---|---|---|---|
| AReaL | 9/10 | 9/10 | 1 | 0 | 22,540,704 / 597,920 | 28 / 709 |
| Codex | 10/10 | 9/10 | 0 | 1 | 17,116,287 / 352,830 | 134 / 848 |

两方各两个网页任务均通过真实 Chromium 检查，共 4/4。Codex 文档题原评分要求 stdout JSON，但公开题面没有该格式要求；保留原 FAIL，验收记 UNKNOWN，不加成功分、不修改冻结断言。前轮日志题“静态报告是否必须由 CLI 生成”的歧义同样保留 UNKNOWN。

双方正常且行为通过共九对、覆盖九题，按题等权的 AReaL/Codex 墙钟几何比为 **1.4111**。全尝试墙钟中位数分别为 892.1 秒和 588.5 秒。配对统计有成功筛选偏差，且每题仅一次；既不能代替固定分母，也不能与故障污染的旧矩阵相减解释为因果收益。

完整用量配对为零。已观测 cached input 下界分别为 4,430,080 和 7,398,272；属于 input 的子集，不能再次相加。精确 token 比、费用比和美元费用均 UNKNOWN，请求覆盖率不等于 token 覆盖率。

本轮确实使用了并发：请求服务区间重叠因子的题间中位数为 AReaL 1.98、Codex 2.40；区间包含网络、排队、推理和流消费，不是 GPU 利用率。原 100 次根槽利用率约 99.7%，但故障阶段的满槽不代表有效产出。最终 AReaL 的最后子回执后中位时长为 183.3 秒，包含必要整合，不能全部列为浪费。

## 原生回归与未解决问题

最终源码的 `make verify` 通过：Rust **1110 passed / 14 ignored**，fmt、workspace/all-targets clippy、SDK、Python、schemas、launcher、PTY/HTTP/SSE/SIGKILL/trajectory smoke 与文档检查均通过。运行包冻结 103 个文件，最终矩阵前后完整性一致。这里只给机制正确性和本地诊断证据，不替代四领域各 25% 的泛化门禁。

- 真实 Core/Runtime 探针验证共享作者同时等待模型、父任务可写、活跃后台进程保持租约、陈旧命令执行前冲突、取消后资源结算。
- 模型容量为 1 时，故障请求退避期间健康求解和摘要相关探针的准入延迟分别为 69.1 ms、38.0 ms；旧候选约 4028 ms。这是特定故障容量探针，不能写成整题加速比。
- 一次已确认写入后两次真实 TCP 断流可恢复完成；六次断流会在五次 Core 恢复后失败。两种情形写入都只有一次；显式 disable 仍失败，UNKNOWN 用量保留。
- 隔离 Node、授权网络、秘密读取拒绝、503 恢复、完整报告交接与取消终态回归通过。最初忘记给回环地址配置 NO_PROXY 的探针超时单列，正确环境重跑通过，未删除初始失败。

最终轨迹的 17 份可见隔离 worker 均一次执行完成，无旧失败锁存；根 final 为 AReaL 九次各一份、一次零份，Codex 十次各一份。没有检测到同一终态页面反复读取或动态前缀变化，也没有递归子派发；没有复现不等于所有任务循环已消除。

长尾仍然存在：离线文档题在 1156.3 秒继续增加故障边界测试，1174.9 秒收齐 23 项测试通过结果，但 `verification.md` 与根 final 未交付，随后达到 20 分钟墙钟上限。另有六次过早读取未结算制品被拒绝、一次 UTF-8 分页偏移无效。这些是剩余协调和决策开销；制品准入、必要集成和安全检查没有为了提速被绕过。没有再增加题目专用提示、单方预算或付费重跑。

本次交付本身也有编排效率问题：原 100 次模型执行跨度约 80.6 分钟，主开发对话另有约 6.47 小时无记录空档，原因 UNKNOWN，不能归给 AReaL 单题性能。开发消耗与双方作答用量单列，reasoning 属于 output 子集；不隐瞒开发失败与开销。
