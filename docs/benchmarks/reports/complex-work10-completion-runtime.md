# 复杂任务收尾、制品就绪与运行策略继承

运行包 `41805761f94c080a4aa81383a501fccc8d7548e6` 已通过机制回归、固定100次开发集对照并安装到本机 GUI。43个双方正常且功能正确的配对中，按任务等权的墙钟比为 **1.1018**，AReaL 仍慢约10.2%。长尾尚未消除：AReaL 2/50达到墙钟上限，产物通过但没有正常结束。数据与全部100格结果见[可移植汇总](complex-work10-v1.1-summary.json)。

旧“慢41%”使用的中继丢失了 Codex 原生协议及路由头，不能作为可靠的原生前后因果基线。不能将这里的结果表述为已证明“从41%优化到10.2%”。两次测量的原始结果、无效批次和失败均保留。

## 问题类别与修复

| 问题 | 实现与验证结论 | 保守边界 |
|---|---|---|

| 共享作者整轮独占 | 前一轮已增加安全快照/CAS和资源结算后的模型等待让出租约；本轮回归未发现回退 | 活动进程、未知副作用或无法确认一致性时仍独占；不能任意逐工具解锁 |
| 网络退避占名额 | 求解、摘要和共享模型按实际请求占容量，退避释放后重新排队；容量1时健康请求能进入 | 持续重试仍为兼容默认，本机显式 bounded；HTTP重试与流恢复是两层预算，未知写入不重放 |
| 隔离快照不适应仓库 | Git感知源码投影保留已跟踪、未忽略脏源码及显式写集合；忽略构建产物不污染输入 | 单文件16 MiB、总树64 MiB；符号链接、超限、环境依赖仍可能拒绝隔离或保守共享，不是完整环境克隆 |

| 取消后重复收尾 | 取消、失败、中断等已结算终态均参与消费判断；本轮AReaL50根未见相同最终答复重复 | 只确认实际完整观察的内容；迟到新结论与清理变化仍须唤醒 |

| 动态轮数破坏前缀 | 既有修复将动态提示留在运行上下文；本轮逐请求前缀变更0 | 原缺陷有显式配置触发条件，不泛化到全部GUI行为 |

| 重复读取/唤醒 | `receiptVersion`与 `agent_wait_any.after/nextAfter`只跳过未变化的已结算回执；本轮版本化等待103次、相同终态分页重复读取0 | 游标不是正文已读确认；新内容、错误、交付及资源释放变化不可吞掉 |

## Codex实现参照与测量正确性

固定参考源码为 `014489466a1739c2c563cdfe57880c2c7c8680e3`。其 `codex-rs/core/src/tools/parallel.rs`按工具声明的并行能力使用读/写锁和可取消准入；`tools/handlers/multi_agents/wait.rs`使用 `FuturesUnordered`等待首个终态。AReaL据此采用明确安全类别、顺序屏障和结果驱动等待，保留自身持久意图、资源清理和UNKNOWN约束。共享写入的一致性边界不直接等同于Codex的工作目录策略。

实际CLI二进制SHA256为 `1afb28c01d7d49e892bd75f11076b10f1451e34e0ee308a95e5ab7f69f9c84fe`；其与缓存参考源码的精确编译对应为 **UNKNOWN**。Code-mode内部工具及子任务事件不是双方完全对称可观测的字段，缺失不能填0。

本地捕获真实CLI请求确认旧桥丢失 `x-openai-internal-codex-responses-lite`、session/thread及其他原生头，也未双向传递turn-state。旧桥批次8个根及准入探针独立留存；不因分数选择重跑。新桥保持双方原生请求、双向路由头和SSE字节，可信层覆盖认证，去除跳点头及解码后失效的长度/编码，不添加隐式重试。3项头契约和2项真实HTTP wire检查通过，再完成双方真实准入。固定100次中仍有真实传输故障和模型容量拒绝，不能称为零故障链路。

两方采用同一模型 `gpt-6.1-sol`、`xhigh`、low冗长度和default服务层级；十题各五次，每方3个根槽，1200秒外部根墙钟上限。结束即补位，独立验收不占根槽；失败不重跑、不单方扩预算。本批全部属于已见开发集，重复不构成新的来源隔离证据。

## 为什么仍慢，为什么本次对照耗时较长

滚动调度的三槽利用率分别为98.81%和98.04%，从根结果结算到新准入的中位延迟约1毫秒；此值不掩盖根结果内部的观察器结算耗时。正式矩阵总墙钟约3小时54分，AReaL三槽结束跨度14016秒，Codex11990秒。按同一账号稳定链路探针选择3槽，未为了赶时间继续增加容量；容量探针失败均保留。这里的完整验证有明确100次分母，不因尾部慢而再开启下一批。

剩余差距在任务内部可见：AReaL服务区间重叠较低、最后子模型响应之后的尾部较长。门户第2次在1068秒完成浏览器检查后，又撰写4703字节验证报告、复跑9项HTTP测试、晚读截图，再发起元数据计划更新；该请求未收到完整终态便到达外部截止时间。第4次离线文档生成也达到墙钟上限。两次均无正常最终答复，不属于已经修复的重复最终答复消费问题。

这些轨迹支持继续减少不必要复验、让文档与验收更早进入可并行工作以及减少晚期元数据轮，但不能把所有集成验证算浪费。模型服务区间包括网络、上游排队、推理和流消费，无法精确拆成纯计算或工作区锁等待；不能根据单个区间认定锁是主因。当前策略未完全解决尾部，未晋级全局性能默认。
