# 0010：复用 Core 收据，重连替换快照

当前 Core 已有持久业务 requestId 与原子快照订阅。Remote 在现有桌面提交 journal 中关联设备 commandId 与原生 requestId，恢复时查询原收据并替换投影；不新增云端执行账本或耐久事件回放平台。

这保留了 Core 的 UNKNOWN、容量、并发准入与审批语义，并避免网络重试制造重复执行。代价是结果不明时可能必须等待/人工核对，而不是提供看似无缝的自动重试。没有公开收据查询的操作只能报告明确响应或观察到的目标状态，不能伪造因果确认。

已有事件窗口属于可丢弃的显示投影。网络恢复不意味着 Agent 进程恢复，Agent 恢复也不意味着重放未知副作用。
