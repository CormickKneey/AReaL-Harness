# 普通会话暂停后在原会话继续

状态：accepted。产品语义已确认，尚不表示实现与验收完成。

普通会话的停止目前结束当前 Turn，用户可以在原 Thread 再发送消息，但缺少明确承接未完成工作的“继续执行”入口。决定保留原会话、原目标和已发生的进度，由用户手动选择继续，以支持跨应用、后台服务及电脑重启后的续做。

## 已确定的语义

- 暂停保留未完成工作的目标、历史及既有成果；继续仍属于原主会话，不要求用户重新描述原要求。
- 再次打开应用或会话时显示可恢复的状态，由用户点击“继续执行”后才推进；打开会话、恢复连接本身不启动执行。
- 继续根据历史事实和当前工作区实际情况承接剩余工作，不承诺冻结或复活旧模型请求、命令、进程及精确执行断点。
- 操作结果不明时先核对结果，再继续；恢复不能把未知操作当作未发生而重新执行。

## 交互与执行范围

运行中将现有主要停止操作表达为“暂停执行”，暂停后在同一主要操作位置提供“继续执行”。正常完成后的普通会话沿用现有结束机制，等待用户下一次输入；不因增加继续入口而自动转为跨轮持续推进的 Goal。

电脑断电、Core 崩溃等意外中断也提供手动继续路径，明确展示“执行意外中断”及已知原因。已有失败分类和操作 UNKNOWN 必须保留，不能为了显示暂停而覆盖原始执行结果。

暂停后输入框为空时，主要操作显示播放图标，名称为“继续执行”。有新输入时切换为普通发送图标，内容作为原会话中的新用户消息发送，可以补充或改变要求，不包装成恢复旧目标的隐藏指令。编辑草稿本身不启动执行。

## 取舍

保留目标与进度允许用户隔一段时间回来接着完成工作，不依赖旧执行资源仍然存活。代价是历史观察可能已过时，继续时需要重新检查相关现状；已经产生的文件或外部变更也不会因为暂停而回滚。

选择精确执行断点恢复会要求保留模型流、工具及外部资源状态，无法作为普通会话跨重启恢复的统一保证，因此不采用。

## 编辑最后一条用户消息

最后一条用户消息提供铅笔编辑入口。用户可原地修改 prompt，选择取消或发送。取消保留原消息；发送将修改后的内容作为同一会话中的新用户消息执行，保留原回复及全部执行记录。界面明确提示按新消息发送，不撤回已经发生的文件或外部操作。不扩展为任意历史消息编辑或历史版本树。

## 队列与历史

暂停保留已有排队消息和用户调整后的顺序。继续时优先处理这些已发送要求，不越过后来补充的限制。

不新增独立的放弃工作流程。暂停可以一直保留；用户可以处理待发送消息后使用现有归档收起会话。归档保留历史。

升级前的普通会话，只要最后一轮明确为中断，也提供继续入口。缺少可靠原因时显示“执行已中断”，不猜测主动暂停或异常退出。正常完成的会话不因此显示待继续状态。

现有执行、UNKNOWN 和 Goal 恢复约束以 [Core 契约](../api/core.md)为准。主会话、轮次与暂停、继续的含义见[产品术语](../../GLOSSARY.md)。
