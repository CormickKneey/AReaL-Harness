# 委派与交接

AReaL Harness 的委派让 Agent 承担可分离的工作。用户仍需看清谁负责结果，以及何时能继续操作共享资源。

## 委派是有职责的选择

`R-DELEGATION-001` 只有职责可分离、结果形式明确且协调收益值得时，才需要子任务。简单或强依赖的工作可以留在主任务，不把 Agent 数量当作进度。

`R-DELEGATION-002` 子 Agent 使用独立上下文和历史，权限继承或收窄。职责说明决定它负责什么，不能代替权限授权。父子身份的展示归 [身份与所有权](identity-and-ownership.md)。

`R-DELEGATION-003` 共享执行与隔离执行的选择由 Core 按意图、授权及环境能力决定。界面解释职责与实际执行方式，不要求用户通过选择后端来完成普通委派。

## 报告、检查与交付

`R-DELEGATION-004` 阶段报告说明进展和剩余工作，不结束子任务。最终回复也不能单独证明检查通过或修改已交付。

`R-DELEGATION-005` 执行状态、检查状态和交付状态各自回答不同问题。候选修改可以已生成但未检查，也可以已检查但尚未应用。用户需要看到相应事实。

`R-DELEGATION-006` 父 Agent 收到子结果不等于已验证结果。结果提供给模型的证据范围归 [上下文与证据](context-and-evidence.md)。

## 停止后的交接条件

补充指令用于协作，不承担紧急取消的含义。停止请求表达停止意图，文件接管要等实际资源释放和持久结算。

`R-DELEGATION-007` 短暂等待超时、文件没有变化或一段旧交接文字，都不能单独证明子任务已经停止。结果未知时沿用 [控制与审批](control-and-approval.md) 的核对语义。

`R-DELEGATION-008` 普通子执行受父 Turn 管理，TaskRun worker 可以跨协调 Turn 存活。父会话一轮结束不能统一解释为全部后台工作已结束。

定时任务的暂停只阻止后续触发，停止当前 Run 是另一个操作。界面允许暂停计划与当前执行仍在收尾同时成立，最终结算依据 Run 和 worker 的状态。

## 契约与呈现

[委派设计](../../docs/design/multi-agent.md) 维护准入、执行方式和生命周期。[子任务停止契约](../../docs/api/core.md#子任务停止与计量收尾) 维护资源释放和计量收尾。[Task API](../../docs/api/tasks.md) 维护计划与当前执行的控制边界。

`R-DELEGATION-009` 任务进展如何排列、展开与回看归 [任务进展](../patterns/task-progress.md)。这里不增加新的控制入口，也不把后端已有能力视为 GUI 已完整呈现。
