# 共享设计意图

从用户要完成的工作进入设计，再选择客户端表达。共享层描述意图和可观察结果，平台层决定操作、布局和呈现。下表是跨端设计地图，不新增 Core 状态枚举或页面渲染 DSL。

| 用户意图 | 共同的设计结果 | 平台表达与约束 |
| --- | --- | --- |
| 定位任务 | 知道当前项目、会话或命令作用范围 | GUI 和 Web 导航，TUI 会话选择器，CLI 的参数及结果身份 |
| 输入与提交 | 区分待提交输入、已受理和结果待核查 | 图形编辑器、终端输入和命令输入分别实现；原生 IME 只在相关平台验收 |
| 观察执行 | 分清父任务、工具、子任务与最终结果 | 可折叠过程、终端历史或协议事件，不以模型叙述代替工具事实 |
| 阅读与探索 | 信息有层次，用户可取到必要详情 | 图形面板、终端展开与滚动、CLI 可选输出模式；不要求相同几何 |
| 选择与确认 | 看到实际影响，区分操作中、成功、拒绝和未知 | 现有审批卡、TUI 选择或受支持的交互通道，权限由原业务契约判断 |
| 打开与返回 | 辅助查看保留所属任务和继续工作的路径 | 窗口焦点、浏览器返回和终端焦点分别验证，关闭查看不推导后台取消 |
| 调整偏好 | 理解设置范围和生效时机 | 保留各端现有主题能力与持久化，跨设备同步需单独产品决定 |
| 异常与恢复 | 知道受影响范围和合法下一步 | 文字、状态和动作可不同，UNKNOWN 不被改写为已失败或已成功 |

GUI 的八类交互族及现有规则 ID 继续由 [interactions.md](../../clients/gui/design-system/interactions.md)维护。TUI 和 Web 的现有行为见[客户端指南](../../docs/guides/clients.md)。本文件不复制那些平台规则或宣称已经统一。
