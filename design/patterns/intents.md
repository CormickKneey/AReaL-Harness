# 共享设计意图

从用户在 GUI 中要完成的工作进入设计，再选择操作、布局和呈现。下表连接设计意图与 GUI 实现约束，后续 Web 复用时核对浏览器适配，不新增 Core 状态枚举或页面渲染 DSL。

| 用户意图 | 设计结果 | GUI 表达与约束 |
| --- | --- | --- |
| 定位任务 | 知道当前项目、会话和任务作用范围 | 导航和详情保留当前对象及所属任务 |
| 输入与提交 | 区分待提交输入、已受理和结果待核查 | 输入区保留草稿、提交状态与原生 IME 行为 |
| 观察执行 | 分清父任务、工具、子任务与最终结果 | 按真实事件组织可折叠过程，不以模型叙述代替工具事实 |
| 阅读与探索 | 信息有层次，用户可取到必要详情 | 消息展开、资源面板与滚动保留阅读上下文 |
| 选择与确认 | 看到实际影响，区分操作中、成功、拒绝和未知 | 审批卡绑定真实请求，权限由原业务契约判断 |
| 打开与返回 | 辅助查看保留所属任务和继续工作的路径 | 核对窗口、面板与原生视图的焦点和返回，关闭查看不推导后台取消 |
| 调整偏好 | 理解设置范围和生效时机 | 保留 GUI 现有偏好所有者与持久化，跨设备同步需单独产品决定 |
| 异常与恢复 | 知道受影响范围和合法下一步 | 文字、状态和动作可不同，UNKNOWN 不被改写为已失败或已成功 |

GUI 的八类交互族及现有规则 ID 继续由 [interactions.md](../../clients/gui/design-system/interactions.md)维护。本文件不复制实现规则；后续 Web 接入时仍需独立验证导航、输入、焦点与浏览器能力。
