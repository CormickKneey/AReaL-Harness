# 反馈与恢复

先决定用户需要理解的事实，再选择样式、文案和合法动作。本页维护通用状态的展示与动作约束。请求与审批的业务含义见[控制与审批](../people-and-agents/control-and-approval.md)，实际恢复保证由原执行契约决定。

## 状态必须先于样式决定

| 状态 | 展示与动作 |
| --- | --- |
| 首次加载 | 所属区域显示加载状态；无假数据，无可误触操作 |
| 刷新 | 保留已确认内容，局部标识刷新；请求失败时旧值不伪装为新结果 |
| 空 | 说明为何为空；只有存在可用下一步时提供动作 |
| 提交中 | 防重复提交，保留动作标签/草稿；只禁用受影响动作 |
| 成功 | 显示权威回执后的当前值；必要反馈就近出现 |
| 失败 | 明确原因及可行恢复，保留输入；无条件重试不作为默认 |
| 待确认 / UNKNOWN | 与失败、成功分开；核对原请求，不以新身份重放 |
| 不可用 / 无权限 | 显示真实原因与适用入口，不生成虚假开关或无效按钮 |

## 反馈的范围

反馈绑定受影响的任务、字段或资源。局部问题保留其他可用内容，不用全局失败遮住已经确认的结果。反馈同时使用可理解文字，技术详情按需展开。成功、结果刷新和计量结算分别表达，不因后续刷新失败推翻已知结果。

GUI 的实际组件、错误展示和恢复入口见[交互族](../../clients/gui/design-system/interactions.md#i-recover-异常与恢复)。TUI、Web 与 CLI 使用各自输出和控制能力，不将同一套控件强加给所有入口。
