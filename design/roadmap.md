# 设计系统建设顺序与缺口

AReaL 已有生产控件、GUI 目录、状态合同和开发预览。当前共享目录已有原则、基础、内容、人机关系、模式、组件、产品和决策。首条文档纵切连接术语、反馈措辞、基础角色、工作台和就近组件合同。[完整工作台候选](products/workbench/candidate.md)将这些选择组合成一条可操作的本地任务路径，供整体评价。下一步按评价收敛选择，再迁移生产路径。下表分别列出现有基础与未完成工作。

## 当前基础与缺口

| 能力 | 当前基础 | 仍需完成 |
| --- | --- | --- |
| 产品设计语言 | [共享原则](principles/README.md)、[表达角色](foundations/roles.md)、[完整工作台候选](products/workbench/candidate.md)沿既有角色形成整体 | 用户评价文字层级、表面、密度、形状、状态和动效，并收敛下一轮选择 |
| 内容与文案 | [术语](content/terminology.md)、[界面文案](content/interface-copy.md)已区分用词建议与执行事实 | 随真实入口采用并核对翻译、范围和反馈，不做脱离功能的全局替换 |
| Token | [角色与平台映射](foundations/tokens.md)，[浏览器焦点共享源](tokens/focus.css)已接入 GUI 与本地 Web | 首组焦点已通过真实隔离 Core 的 GUI 与本地 Web 键盘审批路径；下一组按真实消费者选择，动态偏好和终端能力继续由本端拥有 |
| 组件合同 | [组件选择与职责](components/README.md)已连接首批就近合同，生产控件及平台合同保留原所有者 | 核对合同与真实消费者，补齐实际缺失的行为证据；Props 由类型提供 |
| 用户任务与组合 | [共享模式](patterns/README.md)、[完整候选](products/workbench/candidate.md)已串联任务、过程、审批、资源与设置 | 用户评价整体体验，再分别迁移和验证真实控制器 |
| 文档与可运行示例 | [文档与预览入口](README.md#阅读与预览)、现有 catalog 与生成器 | 核对原 Markdown 链接、合同和生产示例的阅读路径；运行结果另行记录，不以构建代替用户路径 |

当前文案是采用建议，工作台包含设计要求、源码映射与本地可操作候选，就近合同也不等于生产行为验收。文档入口和已有示例形成首条阅读路径，真实路径迁移仍待验证。GUI 的 [Base 候选](../clients/gui/design-system/base.md)仍未冻结。现有目录主要检查引用与声明，不能证明实际 JSX 采用了对应组件，也不能代替视觉或平台验收。

## 先形成完整候选，再收敛实现

1. 固定一个完整设计版本。以提交任务、观察工具、处理决定、查看资源和返回阅读为主路径，同时安排一次外观设置修改。列出必要的失败与未知结果，固定明暗、字号和宽窄条件。交付可操作候选、关键状态和设计决定，先评价整体体验。
2. 明确首批基础角色。结合候选决定文字、表面、反馈、间距、形状和图标的使用关系。对 GUI、TUI 与 Web 分别登记适用范围，图形几何不强求终端等价。输出角色到当前实现的映射，明确哪些默认值需要共享。
3. 收敛一组 Token 与组件。先迁移候选实际使用的一组角色及 Button、Select、Switch、Feedback 等控件。共享默认值只有一处可编辑源，平台输出可重复生成并检查漂移。用户偏好保留运行时输入。迁移调用方后删除被替代定义，不同时维护两套数值。
4. 核对文档与真实示例。首批就近合同和共享内容已进入文档目录。复用现有预览核对组件状态、组合、主题、字号和平台限制，跨端理由归 `design/`，类型提供接口事实。下一步候选是核对目录声明与实际导出，以及从同一元数据提供检索，不另写一套 Props 或组件名单。
5. 迁移首条生产路径并复验。绑定原有业务控制器，分别检验权威结果、草稿与身份、阅读与焦点。跨端复用另取一个 TUI 或 Web 同意图场景，不能用 GUI 结果代替。完成后用另一种任务检查共享规则，再决定扩大 Base 准入。

共享默认值的生成格式在第二步确定。DTCG 可作为候选，但不为采用某种格式提前搬运所有数值。独立发布组件包、独立文档站和专用 Agent Skill 都不是首轮前提。先让现有生产组件、文档和示例形成可复验的最小闭环，有独立消费者或明确检索需求后再扩展。

验证证据的职责边界统一见[架构](architecture.md#验证边界)。以下条件用于下一轮产品建设，文档归档不自动满足这些条件。

## 首轮完成条件

- 同一候选覆盖工作区、对话、资源、设置及所选异常路径，整体视觉决定可审查。
- 所选 Token 和组件有明确所有者、真实消费者、状态合同与验证位置。
- 文档中的示例使用生产实现，目录生成与漂移检查通过。
- 行为、视觉、原生平台与安装包分别报告实际覆盖，未覆盖项保留。
- 原有调用方完成迁移，被替代定义删除，新增任务能复用同一设计选择。

本目录只维护中文。平台现有文档与外部用户文档继续遵循各自的维护约定，不在本轮批量删除既有译文。
