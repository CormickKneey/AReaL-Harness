# Spec 实施与源码判断

本轮在 `codex/gui-specs-20261025` 集成最近分支，并以 `origin/claude/youthful-brahmagupta-tbk3g4` 的 spec 为目标。Spec 描述目标，源码、协议和受控配置描述现有行为。这里记录二者不一致时采用的边界，不把源码实施、局部检查和产品验收混为一项。

## D1 的入口与准入分别建模

[Base](../design-system/base.md) 的固定切片不承诺全部成员都是包导出。Renderer 继续持有 `Feedback`、`ApprovalRequest`、`Messages`、`TurnProgress`、`TurnExecution`、`ToolEvent` 等生产所有者。UI 包按已有合同拆分稳定、组合和实验入口；实验消费者按文件和符号登记。拆分入口不自动提升组件的准入身份。

## D2 保留真实业务样式所有者

用户确认本轮保留必要的业务样式，逐项记录原因、消费者和退出条件，原 3500 行及 5 份非布局文件目标延期。采用率仍须达到 70%，`workbench.css` 字面量仍须为 0。规则与精确清单见 [D2](D2-design-system-adoption.md) 和 [style-exceptions.json](../design-system/style-exceptions.json)。

仓库格式器会展开旧 CSS。迁移前后必须使用相同格式比较，不能把排版展开计为新增业务样式。新增生产 CSS 仍只能是使用 Token 的 `*.layout.css`。不会把标注、图表等业务样式改名成布局，或移入没有真实公共消费者的 UI 组件。

## D3 与 D4 区分颜色等价和可访问性修订

语义色派生关系由声明式公式及现有生成器维护，不引入运行时解释器。D3 的等价比较固定主题、明暗、字号和解析后的浏览器颜色。D4 随后修正默认对比度，因此最终颜色不能再对所有角色断言与修订前完全相同。已批准的角色变更登记在 Base 候选版本的现有记录中。

默认主题的正文与背景按实际配对阻断，自定义主题保留独立诊断。JSX 可访问性检查复用精确存量指纹；新增问题不能通过重建基线消失。自动化键盘和 axe 结果不代替真人 VoiceOver 验收，也不把 Base 候选版本自动冻结。

## D5 复用现有规则所有者

文档收敛沿用规则 ID、registry、组件合同和中英文入口，不建立第二份规则库。活跃文档体积的前后比较使用同一范围；加入 UI 包及 Renderer 合同后的扩展范围另报，不能把不同集合比较成同一降幅。生成的站点同时提供正确的文档链接和所需 JSON 资源。

Agent 对照实验使用同一实现提交、不同文档快照。准备前与准备后的代码摘要均须跨组一致。三项任务各重复三次，两组共十八个独立上下文；保留真实模型调用、检查、读取记录和独立评审。累计读取 Token 是指定 tokenizer 的代理指标，不等于模型的完整上下文。实验脚本存在不代表实验已执行。D5 实验保留为源码冻结后的独立验证，不阻塞实现冻结。

## E1 保留尚未归因的 macOS 启动边界

同机原生夹具取得子 PID 后观察到信号 9，子进程没有首条报告。日志没有绑定发送者，不能归因为 AMFI、TCC 或某个安全产品，也不能据此认为另一个同 Team ID helper 可替代系统解释器。

Python 调用分布在 GUI、共享服务、Runtime 客户端、原生执行和轨迹入口，分别持有 FD、组与会话、owner-death、PTY 和退出回执。仅替换两个入口不足以删除安装依赖。当前保留既有桥接，实施阶段 0 的依赖准入。GUI 先尝试附着后台，仅新启动时预检；安装操作由用户显式触发固定的 `xcode-select --install`。原生替换仍需可归因的进程证据、干净 macOS 环境及签名分发包的生命周期验收。

## E2 按命令与操作关联精确类型

Desktop 命令、IPC 通道和 Rust RPC 方法是三个命名空间，名称集合不要求相等。唯一的命令表声明路由、作用域和读写语义；共享合同按领域维护请求及响应。`Action` 与 `call` 同时保留命令、操作和响应之间的类型关联，不把其余命令统一退回 `Promise<any>`。

Main 自有 JS/CJS 逐文件启用 `@ts-check`，完整应用配置纳入自有源码。全局 `checkJs` 保持关闭，避免顺着依赖图审计第三方源码；这不排除自有文件。原始 preload 和网络响应在解码前保持 `unknown`，边界通过后使用类型，不以重复散落的谓词代替领域模型。完整命令校验器在首次调用时加载，加载与请求校验完成后才提交。轻量传输错误与 MCP 页面消息守卫保留独立的共享所有者，避免把全部管理响应与 SDK schema 纳入初始静态闭包。

管理合同复用 `schemas/areal-core-v1.json`，生成静态 JSDoc 与谓词。实际 Core 投影与 schema 不一致的部分在生成器引用生产者并作明确映射。MCP Tool 和 Icon 复用已有官方协议 schema，不重建宽泛的元数据对象。`contracts:check` 只读检查生成物是否漂移。

响应解码失败不能证明写入未受理。既有错误结算保留原请求身份和 UNKNOWN，只核对原提交，不自动重放。范围仅覆盖外层公开命令合同及其必要消费者，既有 Renderer 内部的整个动态投影域不在本次迁移中。

## E3 与 E4 沿真实生命周期拆分

App 的领域状态、选择订阅和视图沿现有窗口作用域拆分。外部 store 的生命周期仍属于窗口，不把执行资源移进 Renderer。`AppContent` 保留必要的编排，因此不为达到任意函数行数而建立无独立职责的包装。

Preview 的纯解析与匹配规则移入纯模块，原生窗口、WebContentsView、输入和释放回执保留在 Electron。只读审批计划、截图守卫和批量防重放记录的生命周期不同；Map 消费位置、实时 owner 检查及 await 顺序保留在原生所有者。纯模块和原生资源模块采用不同的尺寸目标，不把整个控制器改成巨型 reducer 或方法转发层。

`utilityProcess` 的判断依赖真实事件循环及输入测量。60 秒诊断定时偏差不是事件循环 p99，不能据此决定进程隔离。

## E5 区分平台注册与实际资格

测试清单声明层级、平台、领域和前提。临时目录由公共 helper 创建，路径检查基于 AST，避免把 Linux 环境限制当成产品通过。重复运行器保留首跑结果、失败和 blocked；重新运行成功不删除前一次失败。macOS 与 Linux GUI 的重复资格及未发布分支的远端 CI 分别报告。

## E6 保留构建优化，性能交付延期

终端与 Markdown 编辑器已有延迟加载，继续保留。完整 Markdown 渲染器按需加载，等待状态本地化，失败显示转义原文。字节预算从实际 Vite 产物的 HTML 入口与静态导入闭包计算，包含 modulepreload。

用户明确将本轮性能交付延期，包括 E3、E4 共用性能专项及 E6 启动、内存和前后实测。已提交的懒加载、预算和测量工具保留，未执行项不能登记为通过。

测量工具使用隔离的普通构建和公开 React Profiler 构建，保留相同生产配置与工作量。流式增量、重内容首次使用、大型原生 DOM、多 iframe 及真实输入分别记录。CPU profile 在独立诊断运行中采集。启动记录进程冷重启、保留的合成历史及内存口径，不声称清空了操作系统缓存。构建体积变化不证明耗时或内存改善。

## 首次健康基线和验收边界

本功能首次落地健康基线。最终值依据同格式源码、实际生产范围及已确认的 D2 例外建立。存量大文件逐路径记录，新增模块仍受现有上限约束；不引入通用预算豁免。采用率沿现有收集器追踪实际重导出，预览、生成物和 vendor 不纳入生产范围。

源码检查、真实 Electron/Core 路径、性能测量与 Agent 实验分别保留结果。确定性本地模型不证明真实供应商、物理 CUA 或真人 VoiceOver 通过。干净 macOS、安装包、签名公证和远端 Linux CI 也需要各自证据，不由本机类型检查或源码构建推定。
