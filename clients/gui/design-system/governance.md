# 变更、证据与验收

## 变更准入

优先顺序：复用模式 → 复用组件与变体 → 在现有所有者补充真实缺失的状态 → 必要时新增公共角色。新增 Token 需说明用途、现有角色为何不适合、实际消费者和主题/偏好影响；不按截图上的偶然颜色命名。

新增模式或公共变体，在对应规则文件登记适用任务、默认状态、生产所有者及验收条件。局部例外在变更说明中写明规则 ID、文件/组件、具体原因、证据和退出条件；持续例外在所属规则旁维护。例外必须有范围，不能整文件豁免。图标固有色、语法高亮、图表等先核对已有所有者，不以“特殊设计”为由绕过语义角色。

v1 不对存量页面做批量迁移。发现差异先登记在[覆盖与缺口](inventory.md#覆盖与缺口)中对应范围；只有阻碍当前任务或由本次变更造成的差异才扩展实现范围。

系统级登记、页面合同和生成检查见[自动化机制](automation.md)及[结构化流程](structured-flow.md)。`verify:design` 检查这些声明与派生物，但不静态证明 JSX 符合声明。

## 证据分层

| 证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| 源码、类型与静态审计 | 接口存在、依赖与已扫描范围的 Token 使用 | 用户能完成任务、视觉一致 |
| 生产组件 fixture | 挂载的组件、主题、字号、宽窄和列明状态 | Core、真实供应商、安装包、原生窗口 |
| AReaL 真实桌面 | 该源码/包及该场景的窗口和交互 | 未运行的平台、账号、其它场景 |
| Codex 实例截图 / DOM | 该版本该状态的参考外观与可见结构 | AReaL 已实现、内部尺寸规范、未观测交互 |
| 官方网页中的产品插图 | 指定公开参考图的视觉构图 | 当前本机 Codex 或动态行为 |

每组截图记录：run ID、捕获时间、参考/实现模式、应用版本或源码 SHA 与 dirty 状态、进程/目标、场景前提、到达动作、可见完成条件、主题、viewport、DPR、字号/字体、原图路径与 SHA-256、关联规则、观察/推断/偏差/缺口。未知项写 unknown。证据摘要可入规范，带账号、私有路径或对话内容的原图留本地；发布另按授权范围处理。

截图用于校正规则的顺序是：定位具体状态 → 保存原图和计算样式 → 直接观察 → 与当前规则对照 → 登记采纳或保留差异 → 修改唯一规则位置。只凭截图不推断自动折叠、等待时长或焦点行为；这些需要实际连续操作。

## 有界问题与逐步证据

在既有页面合同和 run manifest 上记录一个可回答的问题：稳定 question ID、所需观察、可反驳条件、关联规则、证据 ID 和待决项。每个 step 记录前一状态、真实动作、可观察完成条件、实际条件与原始材料。观察、推断、保留差异和规则变更分别写明，不要求每个小改动建立完整调查账本。

材料有效性与测试结果分开：完整捕获、部分/裁剪、未请求、不可用分别标明；只有完整可见的材料支持整段视觉结论。超长组合可保留原始部分截图并逐行补采，不能悄悄丢弃失败材料。原图存在或哈希相同不自动证明布局完整、交互相同或设计合格。

成对比较先列出内容、状态、组件实际宽度、字体、主题、DPR及窗口壳层。条件不匹配的维度保留缺口；结构/像素差异和设计判断分别记录。源码静态信息、fixture 和参考观察各自只关闭相称范围的问题。首个有界试用见[设置迁移题](exercises/settings-reflow.md)。

## Agent-browser 采集约定

复用已授权的 CDP 实例，先 `tab` 和 `snapshot -i` 确认目标；每次导航后重新读取 refs。选择偏好、组件与示例场景，避免访问无关聊天。等待明确页面条件后截图，测量具体挂载变体。未观察到的 light/dark、菜单、键盘、错误状态逐项保留缺口。

独立实例由任务授权启动；是否关闭遵从用户当次要求。认证由用户完成，不读取或导出 cookies、token、账号存储；不以连接成功代替登录和目标可用。页面截图不能覆盖 native menu 或 WebContentsView 的独立验收。

## 按改动选择检查

- 仅规范：`python3 scripts/check-docs.py`、`git diff --check`，核对链接与生产导出；无须新增运行时测试。
- 公共视觉组件/Token：`pnpm --dir clients/gui typecheck`、`pnpm --dir clients/gui verify:design`、`pnpm --dir clients/gui design:build`；按现有 `test:design` 保存对应明暗、字号与宽窄状态。
- 业务交互：追加该路径的既有验收；涉及 IME、权限、未知提交、原生窗口时使用相应真实桌面场景。类型检查或 fixture 不能替代。

当前 CSS 静态检查仅覆盖 inventory 中列明的范围，另有目录/合同和生成漂移检查。v1 不宣称新增全仓 lint；评审逐条检查本次新增裸颜色/字号、复制控件、遗漏状态与模式偏离。不要为文档任务安装另一套视觉测试平台。

## 完成条件

每个改动能回答：用了哪个模式和生产所有者；复用哪些状态；宽窄、主题和用户字号是否适用；例外为何必要；证据实际证明哪一层；尚缺什么。机器检查通过后仍需审阅 owned diff，用户保有最终产品验收权。Agent 不自动把自己生成的截图升级为获批视觉基线。
