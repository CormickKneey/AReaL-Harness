# 动态信息流复验题

问题 ID：`Q-CONVERSATION-DYNAMIC-05`。本题是后续 P-CONVERSATION 的实现验收合同，不是已运行通过的AReaL模拟页。输入源码快照为 `2e4e1d69`，Base候选0.1.2；参考为Codex26.1013.31256的合成验证聊天。仅公共规范更新不准入新Base成员。

## 固定路径

准备一段已完成的合成历史、一条新的用户消息、具名短过程、真实工具开始/结束及结果、足够产生滚动的长正文、明确final与完成事件。工具结果和正文增长是不同阶段；不允许以模型自述“执行了命令”替代工具记录。固定内容含段号与末标记，完成条件只从目标助手输出及独立运行状态读取，不匹配用户提示或预测建议。

顺序：接受新消息→过程/工具运行→正文逐项增长→向上回看一段实际可见的历史→至少两个可区分增长样本→明确返回最新→观察继续跟随→展开已有工具详情→完成收敛→再次打开总组及原详情。真实模型可能过快；实现复验使用受控输入事件推进，不直接设置期望的follow/open状态。参考观察不保证所有动作都在同一轮或同一视频段覆盖，需分别标记。

## 反证与验收

| 失败方式 | 必须观察的结果 |
| --- | --- |
| 文字或活动丢失/重排 | 相同身份的内容保留；总组展开后顺序与原始事件一致 |
| 回看被新输出拉走 | 正文仍增长、任务仍运行；实际可见且身份稳定的段落锚点保持阅读位置，而不只比较scrollTop |
| 点击返回就误报已到达 | 单列滚动中与实际到达；后续增长中验证恢复跟随 |
| 完成让最终回答一起消失 | 过程默认按目标合同收敛；final独立可读，异常与未结算资源仍可发现 |
| 刷新或父组折叠重置人工选择 | 同一详情身份的人工展开保留；新组不继承另一组选择，父子状态分别测量 |
| 只展示模拟工具文字 | 独立工具身份与running/terminal/result证据；真实执行还需Core/Runtime结果，renderer不能独自证明 |
| 预测建议误算为回复或提交 | 采样排除输入区；建议出现不增加已受理用户消息 |

代表条件先取参考暗色、14px、1509×949 CSS px、DPR2；实现再选择窄容器/大字号和reduced-motion补充布局边界。参考与实现的字体、窗口和时间条件分别记录，不能据此宣称全矩阵或全平台通过。

## 证据和所有者

复用 Messages、TurnExecution、ToolEvent、CollapsibleText 与原阅读所有者，不新建历史store、页面DSL或自动重放真实提交。先通过生产组件的动态事件题，再按路径选择既有隔离Electron/Core验收；fixture与真实执行分别报告。

按[动态关联证据](../governance.md#动态信息流的关联证据)记录动作、目标回复增量、分组/人工选择、可见锚点、录像段与关键帧。同一collector的时钟原点及跨时钟映射明确；事件先后不依赖不兼容的局部monotonic差值。视频需实际解码并检查关键动作覆盖，record-stop返回成功不足以证明文件完整。失败片段保留，补采独立登记，不拼成无缺口旅程。

未采到的运行中展开、跨完成保留、可见锚点或录像覆盖保持缺口，不能因静态结果合理就写作通过。本题不证明真实供应商稳定性、安装包、原生系统交互或参考内部协议。
