# 结构化数据到高保真实现

本页定义 [架构阶段 B/C](architecture.md#阶段及准入) 的 v1 合同。先明确架构，再形成有证据的 Base，最后固定题目与模拟页面。当前设置控件合同描述已有预览；设置迁移和内容/决策合同描述候选探索题，均不是盲测或已批准视觉基线。

本流程把“要做什么、按什么做、如何判断相符”固定下来。输入是设计意图和受控引用，输出是生产组件的组合及可追溯证据；页面业务状态仍由原所有者管理。它不是将截图铺在页面上，也不是让 JSON 绕过 React/Core 的执行边界。

## 两类数据

[registry.json](registry.json) 是系统级目录，拥有 Token 角色、组件 ID、模式 ID 和最低状态合同；不存数值副本。[surfaces/settings-controls.json](surfaces/settings-controls.json) 是当前预览的页面级合同，引用同一目录。[设置迁移合同](surfaces/settings-reflow.json)与[内容/决策合同](surfaces/decision-transfer.json)演示新内容对已有组合的引用。[对话信息流合同](surfaces/conversation-flow.json)固定逐步投影题的规则引用和检查点，目标为ConversationFlowExercise；本地运行和公共视觉基线分别报告，后者保持pending。修改规范或增加公共组件时维护目录；普通页面变更维护所属合同，不复制全系统规则。

## 页面合同字段

| 字段 | 决定什么 | 校验边界 |
| --- | --- | --- |
| schemaVersion / id | 合同版本和稳定身份 | v1、唯一 ID |
| intent | 用户需要完成的任务 | 必填，语义仍需评审 |
| pattern | 页面组合模式 | 必须在 registry 中 |
| target / runtime | 实现入口与 component-preview / desktop / remote 边界 | 路径存在、runtime 合法；不代表已运行 |
| reference | 已有生产参考，或选定 screenshot / figma 视觉目标 | 代码路径存在；视觉引用必须明确，不能用 nearby option 替代 |
| rules（模式声明时必需） | 引用模式要求的全部规则ID；语义只在模式的ruleSource文档中维护 | ID无遗漏或虚构，规范有唯一定义；不证明JSX遵守 |
| slots | 页面各槽位所用组件 ID | 模式槽位完整、ID 已登记；不是 JSX 执行器 |
| states | 每个状态的到达条件及可观察结果 | 模式必需状态不能缺；实际交互由独立验收确认 |
| conditions | 主题、字号、宽窄与 reduced-motion | 声明本次适用条件，不意味着跑过所有组合 |
| invariants | 跨状态保持的约束 | 非空，语义由评审核对 |
| evidence | pending / captured / compared、artifacts 与 gaps | 非 pending 需路径、SHA-256 和状态；元数据完整不等于视觉通过 |

模式的`ruleSource`与`rules`在registry中成对登记；文档用单个`规则ID`后接中文冒号定义正文。页面合同完整引用ID，不复制规则文字。states可以是多条独立状态轴的验收检查点，不能据此新增Core枚举或全局状态机。

所有路径相对 `clients/gui/`，截图等本地材料的路径仅放本地证据副本；公开合同保留稳定来源、采纳结论与缺口。当前样例明确标记 pending，不能作为 Codex 对齐或 AReaL 运行通过证明。

## 执行顺序与每步完成条件

1. **目标固定**：填写 intent、模式和 target；可从 registry 找到对应生产参考。未找到时说明缺失的能力，不借机自由换主题。
2. **设计固定**：选定 reference，分配 slots，列出 states / conditions / invariants。复用已有生产规则时不要求每个小改动重新画稿；要求高保真复刻时必须指定具体视觉目标。
3. **数据检查**：运行 `verify:design`，坏引用、缺状态、过期目录先修正。结构合格只允许进入实现，不授予视觉通过。
4. **实现**：复用公共组件和默认变体，业务内容填入槽位。新增公共状态先进入生产预览；页面只负责真实数据和动作绑定。
5. **效果取证**：按状态条件驱动真实目标，记录原图与运行条件，再做同状态比较。先检查公共模式的代表状态；只有页面独有内容或布局变化才追加页面证据。
6. **偏差回到所有者**：公共差异修复 Token/组件/组合，局部差异留在页面；以同条件复查。报告五个维度与缺口，用户保有最终验收权。

## 截图取证方案

先把参考和实现分别登记为 run；引用原图及 SHA-256，记录应用版本/源码、dirty 状态、viewport/DPR、主题、字号/字体、内容与交互状态。每帧绑定合同 ID、状态 ID、进入动作和可见完成条件。

优先采集公共控件的代表状态：设置组默认、二值选择、菜单打开、disabled、busy、失败与待确认；随后是对话过程/最终回答、长文本与决策卡片。不同主题、字号与宽窄用代表组合覆盖，不能凭一张总览声称全矩阵通过。Codex 参考只观察展示，不推断其执行协议。

同一帧比较包括：整体层次与区域比例、字体/换行、间距/对齐、语义色/状态、资产/图标和实际文案。全图细节看不清时追加区域图；归一化密度与裁剪后再比较。截图保存不等于 QA；构建成功也不替代同状态视觉比较。

当前阶段先建立自动化数据链和取证合同，截图采集不作为生成步骤；更不自动接受新基线。当前合同的视觉目标和运行证据缺口保留为 pending。

动态信息流按[动态关联证据](governance.md#动态信息流的关联证据)追加事件、阅读锚点及录像关联。任务合同同时写出运行条件和读者动作，例如“正文继续增长时向上回看”，不能只列一个busy截图。真实模型用于观察参考；实现复验可用固定输入事件序列控制外部到达顺序，但必须通过生产组件处理，不直接注入预期的展开或跟随结果。
